Study Guide

Learn Disk Scheduling

A complete reference for your OS exam — concepts, formulas, and comparisons explained simply.

What is Disk Scheduling?

Disk scheduling is the process of ordering a queue of I/O requests to the disk drive. Since disk access time consists of seek time, rotational latency, and transfer time, minimizing seek time is the key goal.

Total Access Time = Seek Time + Rotational Latency + Transfer Time

Key Terms

  • Cylinder: Concentric track on the disk platter — numbered 0 to N.
  • Head: Read/write head that physically moves across tracks.
  • Seek Time: Time for head to move to the target track.
  • Request Queue: List of pending cylinder access requests.
  • Seek Distance: Number of cylinders the head must traverse.

Why Does Scheduling Matter?

Without scheduling, the disk head may jump wildly across cylinders, wasting time. Good algorithms reduce the total head movement, improving throughput, reducing latency, and preventing starvation of requests.

FCFS — First Come First Serve

Requests are serviced in the order they arrive. Simple to implement but may result in high seek times. No starvation occurs since every request is guaranteed service.

Example: Head=53, Queue=[98,183,37,122,14,124,65,67]
Order: 53→98→183→37→122→14→124→65→67
Total: 640

SSTF — Shortest Seek Time First

Always services the nearest pending request. Reduces overall seek time significantly compared to FCFS. However, starvation is possible for far-away requests if nearby ones keep arriving.

Example: Head=53, Queue=[98,183,37,122,14,124,65,67]
Order: 53→65→67→37→14→98→122→124→183
Total: 236

SCAN — Elevator Algorithm

Head moves in one direction servicing all requests, reaches the end, then reverses. Like an elevator. No starvation. Provides a more uniform wait time than SSTF.

C-SCAN — Circular SCAN

Like SCAN but after reaching one end, the head jumps back to the beginning (cylinder 0) without servicing requests on the return trip. Provides a more uniform wait time than SCAN.

LOOK & C-LOOK

LOOK is like SCAN but the head only goes as far as the last request in each direction instead of going all the way to the disk boundary. C-LOOK applies the same optimization to C-SCAN. Both are more efficient than their SCAN counterparts.

Total Seek Distance
∑ |cylinder[i] - cylinder[i-1]| for i = 1 to n
Sum of absolute differences between consecutive cylinder positions in service order.
Average Seek Distance
Total Seek Distance ÷ Number of Requests
Average cylinders traversed per request service.
Seek Time
Seek Time = k × |destination − current|
Where k is time per cylinder movement (ms/cylinder).
SSTF Distance
min( |head − r| ) ∀ r ∈ queue
At each step, choose the request with minimum seek distance from current head.
SCAN — Effective Range
Range = [0, maxCylinder] in each sweep
Head traverses full disk length in each direction before reversing.
LOOK — Effective Range
Range = [min(requests), max(requests)]
Head only goes as far as the extreme requests in each direction.
Algorithm Starvation Efficiency Complexity Best For
FCFS None Low O(n) Simple systems, low load
SSTF Possible High O(n²) Moderate load, no starvation concern
SCAN None Good O(n log n) Heavy load, uniform service
C-SCAN None Good O(n log n) High load, uniform wait time
LOOK None Better O(n log n) Heavy load, efficiency-focused
C-LOOK None Best O(n log n) High load, best uniformity
💡

Remember the Order

For efficiency ranking (same queue): C-LOOK ≥ LOOK ≥ C-SCAN ≥ SCAN ≥ SSTF ≥ FCFS (roughly). This depends heavily on the request distribution.

📝

SCAN vs LOOK

SCAN goes all the way to cylinder 0 or maxCylinder. LOOK only goes as far as the last pending request. LOOK is therefore more efficient than SCAN in most cases.

⚠️

Starvation in SSTF

SSTF can cause starvation because requests far from the current head position may never be served if there are always closer requests arriving. Mentioned frequently in exams.

🔄

C-SCAN Jump

In C-SCAN, after reaching the end (max cylinder), the head jumps directly back to cylinder 0 without servicing any requests on the return trip. This jump counts in seek distance!

🎯

FCFS — No Optimization

FCFS is the simplest algorithm. It does not reorder requests at all. It is used as a baseline to compare other algorithms. High seek time but absolutely fair.
